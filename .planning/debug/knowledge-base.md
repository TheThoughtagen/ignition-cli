## windows-ci-winps-sftp-path — Windows CI: ENUMERATE rel paths shifted by 8.3 TEMP; unix-premise tests vs Windows-runner path rules
- **Date:** 2026-10-16
- **Error patterns:** windows-latest, cfg!(windows), winps_enumerate_reports_files_dirs_and_reparse_points, ENUMERATE, Substring, FullName, rel path shifted, "ot/a b", RUNNER~1, runneradmin, 8.3 short name, %TEMP%, \\?\ prefix, sftp_ops_refuse_hostile_remote_and_local_paths, must be refused, local backslash, SftpOp render, safe_local_path, ssh -G, ssh_g_reports_pinned_options, ssh_g_keeps_odd_paths_literal, globalknownhostsfile NUL, /dev/null, userknownhostsfile forward slashes, option_path, NULL_DEVICE, deploy_transport
- **Root cause(s):** F1 (product, latent): winps ENUMERATE built each rel path as FullName.Substring(callerRoot.Length+1); .NET rewrites a root it normalises (8.3 RUNNER~1 -> runneradmin, `.`, doubled or trailing separators), so on windows-latest every rel lost 3 leading chars (AND-gate: length coupling + 8.3 TEMP root sent without \\?\; production sends \\?\, so live runs never showed it); F2 (test premise): SftpOp::render normalises `\` -> `/` in LOCAL paths on a Windows runner by documented design, but the hostile-paths test asserted refusal of local `a\b` on every platform; F3/F4 (test premise): ssh -G tests expected `/dev/null` and backslash display() while the product sends NULL_DEVICE (`NUL`) and option_path (`\` -> `/`) on a Windows runner
- **Fix:** ENUMERATE pushes (DirectoryInfo, relPrefix) pairs and builds rel = relPrefix + $f.Name (770b38f); SftpOp::render delegates to render_on(windows_runner) and tests cover both branches on every host (e254cbe); deploy_transport expectations come from reported_null_device / reported_path_text, pinned to the exact CI-observed Windows lines (ab8608a). Confirmed green on CI run 38838954722 (head ab8608a, all four jobs).
- **Files changed:** crates/ignition-core/src/deploy/transport/winps.rs, crates/ignition-core/src/deploy/transport/remote.rs, crates/ignition-core/tests/deploy_transport.rs
- **Why not caught:** The `check (windows-latest)` CI gate existed but never ran the Phase 22 tests. Earlier steps failed first on each push (clippy, ubuntu inode test, CRLF README test), and `cargo test --workspace` stops at the first failing binary. The macOS and ubuntu gates cannot execute `cfg!(windows)` branches. Local Windows coverage was compile/clippy only (cargo-xwin). Review accepted "compiled but not run" Windows behaviour (22-05-SUMMARY:204). No test fed ENUMERATE a root spelling .NET normalises.
- **Recurrence guard:** Regression tests that run on every host (pwsh required, never skipped): winps.rs:winps_enumerate_rel_paths_do_not_depend_on_the_root_spelling; remote.rs:local_backslashes_are_separators_only_on_a_windows_runner and sftp_ops_refuse_hostile_remote_and_local_paths (both over render_on(true/false)); tests/deploy_transport.rs:reported_spellings_match_the_windows_runner_observation. Pattern: take Windows-runner behaviour as an explicit `windows_runner: bool` parameter, with `cfg!(windows)` only at the call site, so every host tests both branches. When a Windows-only failure appears, first check whether a `cfg!(windows)` branch is documented design that a unix-premise test contradicts.

## sftp-listing-parser-diff — sftp listing parser differential: a raw newline in a POSIX name forged an entry, str::lines() dropped a name's trailing CR
- **Date:** 2026-10-19
- **Error patterns:** parser differential, security review, sftp.rs, parse_batch_listing_as, line_columns_and_name, split_columns, bare longname, ls -la, ls -lan, LS_NUMERIC_VIEW, raw newline in file name, forged entry, `fake`, trailing carriage return, `y\r`, str::lines(), CRLF, Win32-OpenSSH sftp.exe, utf8.c vasnmprintf, mprintf, ListFormat::Posix, c67e8bc, G1, OpenSSH 8.9 users-groups-by-id, account_home, Remote working directory marker
- **Root cause(s):** (A) Every OpenSSH sftp client prints `\n`, `\r` and `\t` inside a name raw (utf8.c vasnmprintf). Since c67e8bc (23-22 G1), `line_columns_and_name` read any line without the `<dir>/` prefix as the server's bare longname, so the tail of a POSIX name holding `\n` became a forged entry (any name, mode, size) and hid the real one. A bare line is byte-identical to such a forgery, so no parser rule can separate them. (B) `str::lines()` in `parse_batch_listing_as` dropped a `\r` before `\n`, so `y\r` read as `y` (since phase 22). AND-gate: client prints raw bytes (not ours) + unanchored parse.
- **Fix:** POSIX hosts are listed with the new `SftpOp::LsLongAllNumeric` (`@ls -lan`): with `-n` every OpenSSH client formats each line itself with the absolute `<dir>/` prefix, and a ListFormat::Posix line without it is refused (a name fragment cannot hold `/`). Windows keeps `@ls -la` plus the bare read (a Win32 name has no line break). `output_lines` splits on `\n` alone and strips one `\r` per line only when every line ends in CRLF (Win32-OpenSSH 9.5p2 measured uniform CRLF on a pipe). account_home uses it and requires exactly one marker. Commits: c1c5781 (RED), 206998e (fix), 2219faf (live gate harness), ca9cd8f (README). Live gate on ign-lnx-836 (OpenSSH 8.9) parses `-lan`.
- **Files changed:** crates/ignition-core/src/deploy/transport/sftp.rs, crates/ignition-core/src/deploy/transport/remote.rs, crates/ignition-core/tests/live_transport_lnxvm.rs, README.md
- **Why not caught:** No gate existed for this class. No test fed the listing parser a name that changes the line structure (a `\n` followed by a well-formed forged line, or a trailing `\r`). The 23-22 plan reasoned about server line shapes, not about which bytes a name can hold. Review accepted the bare fallback on benign captures. A background security review caught it after the push to phase-23-ci.
- **Recurrence guard:** sftp.rs section "a raw newline or carriage return inside a listed name" (six RED tests, plus `posix_listing_refuses_captured_bare_openssh_8_9_output` and `posix_listing_parses_captured_ls_lan_output_from_openssh_8_9`); remote.rs `@ls -lan` render rows; live gate `lnxvm_listing_capture` with `-lan` and the real parser; 7/7 mutants killed. Pattern: when parsing line-oriented tool output that embeds attacker-influenced names, anchor every line to something a name cannot contain and never split with `str::lines()`. Test names holding `\n`, a trailing `\r`, and `\n` plus a forged line.
