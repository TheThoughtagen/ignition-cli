```rust
/// Map terminal-capability env conventions to a Tier. Pure over an
/// injected env snapshot — tests never touch the real environment
/// (edition 2024 set_var is unsafe; the crate's ENV_LOCK exists but
/// injection is cleaner). Priority order matters:
/// 1. NO_COLOR set non-empty  -> Mono   (no-color.org convention)
/// 2. COLORTERM truecolor|24bit -> Truecolor (de-facto convention)
/// 3. TERM contains "256color"  -> C256
/// 4. TERM missing or "dumb"    -> Mono
/// 5. otherwise                 -> C16
pub fn detect_tier(env: &dyn Fn(&str) -> Option<String>) -> Tier
```

12-02's `build_context` will call it as `detect_tier(&|k| std::env::var(k).ok())` — keep the signature exactly `&dyn Fn(&str) -> Option<String>` so that closure coerces.

**Tests** (inject a closure over a `HashMap<&str, String>` — no real env, no ENV_LOCK needed):
- `NO_COLOR=1` (or any non-empty) → Mono, even when COLORTERM=truecolor AND TERM=xterm-256color are also set (NO_COLOR wins).
- `NO_COLOR=""` (empty) → NOT Mono via NO_COLOR — falls through to the TERM/COLORTERM rules (empty means unset per the convention).
- `COLORTERM=truecolor` → Truecolor; `COLORTERM=24bit` → Truecolor; `COLORTERM=truecolor` + `TERM=xterm` (no 256 in TERM) → still Truecolor.
- `TERM=xterm-256color` (no COLORTERM) → C256; `TERM=screen-256color` → C256.
- `TERM` absent → Mono; `TERM=dumb` → Mono.
- `TERM=xterm` (no COLORTERM) → C16.
