1. `pub fn normalize_descriptor(json: &[u8]) -> Option<Vec<u8>>` — parse a resource.json member; strip `attributes.lastModification` AND `attributes.lastModificationSignature` (the live-evidenced volatility fields — 07-RESEARCH Pitfall 1); keep `scope`/`version`/`files`; re-serialize into a canonical form the normalizer OWNS: after parsing, recursively sort object keys (a small pure `fn canonicalize(value: &mut Value)` that rebuilds every object's entries sorted by key) BEFORE serializing, so output bytes depend only on content — never on input key order and never on serde_json's ambient map behavior (default BTreeMap is sorted today, but a future workspace-wide `preserve_order` feature flip must NOT change canonical output — do not rely on the ambient default). Non-JSON or non-object → `None` (caller hashes raw bytes).
2. `pub fn member_hashes(zip_bytes: &[u8]) -> Result<BTreeMap<String, [u8; 32]>>` — walk members via existing `resource_members`; for each member map to user path via the existing `user_path()`; hash = SHA-256-style digest via a tiny FNV or the existing hashing approach if any — since no sha2 dep exists, use a 64-bit FNV-1a hash rendered as u64 (no new dependency; collision risk acceptable for diff UX, this is not security). For members named `resource.json` (basename), apply `normalize_descriptor` before hashing. Skip directory entries exactly as `resource_members` already does.
3. `pub struct MemberDiff { pub summary: DiffSummary, pub entries: Vec<MemberDiffEntry> }` with `DiffSummary { same, added, removed, changed: usize }` and `MemberDiffEntry { path: String, status: MemberStatus }` where `MemberStatus` is `Added | Removed | Changed | Same` (Serialize as lowercase strings).
4. `pub fn diff_members(zip_a: &[u8], zip_b: &[u8]) -> Result<MemberDiff, CoreError>` — B-relative-to-A semantics: `added` = path in B not A; `removed` = in A not B; `changed` = both, hashes differ; `same` = both, hashes equal. Entries sorted by path (BTreeMap iteration gives this).
5. `pub fn project_meta_delta(zip_a: &[u8], zip_b: &[u8]) -> Result<Vec<(String, String, String)>>` — compare the root `project.json` member's semantic fields `title`/`enabled`/`parent` only; return (field, a_value, b_value) triples where they differ (stringified values). Missing member or parse failure → empty vec (diff is about resources; project.json is surfaced separately as `project_meta`).

Unit tests in the existing `#[cfg(test)]` module: build two in-memory zips with the same helpers the round-trip tests use — (a) identical content + differing `lastModification` attributes ⇒ `same`, (b) member only in B ⇒ `added`, (c) member only in A ⇒ `removed`, (d) differing script bytes ⇒ `changed`, (e) empty-vs-populated ⇒ everything `removed`/`added`, (f) project.json title differs ⇒ delta carries one triple and does NOT appear in member entries status set... actually project.json IS a member; DECISION: `diff_members` EXCLUDES the root `project.json` from resource entries (it is not a resource; surfaced only via `project_meta`). Pin that exclusion in a test. (g) key-order-independence pin: the SAME logical descriptor serialized with two DIFFERENT key orders (top-level shuffled AND nested object keys shuffled) → `normalize_descriptor` emits byte-identical output for both ⇒ identical member hashes ⇒ `same` — the cross-version canonicalization guard proving diff stays honest regardless of serde_json ambient map semantics.
