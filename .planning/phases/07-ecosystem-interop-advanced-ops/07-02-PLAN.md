Planner decisions (research Open Questions resolved):
- **EAM create guard breadth:** `eam_backup` create is unguarded (defaults to `scheduleMode: OnDemand` — never auto-fires); `eam_restart`/`eam_sendProject`/`eam_sendResource`/`eam_sendTags`/`eam_activateLicense`/`eam_updateLicense`/`eam_unactivateLicense` require `--yes`; **`eam_restoreBackup`/`eam_installModules`/`eam_remoteUpgrade` are REFUSED outright** (exit 6 additive slug `eam_task_type_refused`, message names the fleet consequence + points at the v2 EXT-03 backlog scope — honest refusal over guard-everything). ANY non-OnDemand `--schedule-mode` (`Immediate`/`Scheduled`/`AtTime`/`AtDelay`) additionally requires `--yes` (arms autonomous gateway actions).
- **No EAM controller verb:** installMode flip stays a README-documented manual config-resource PUT (gateway-ROLE decision — research Open Question 7, rec adopted). The CLI surfaces the state via `eam_not_controller`.
- **No `ign backup list`:** no native endpoint exists — README honesty over verb theater (research anti-pattern). EAM `storage/archived-backups` is the EAM archive store, out of MVP scope.
- **Deferred EAM reads:** `scheduled`/`retry` list views and `suspend`/`resume`/`cancel` verbs are NOT in v1 (BKUP-02 requires history + create only; each verb carries TUI+golden+README cost) — one README backlog sentence, no promises.
- **force owner resolution:** `eam task force <name>` resolves the owner via task find (`scheduledTaskState.details.owner`, fallback `"eam"`) — one extra round trip, correctness over latency (the 05-04 precondition precedent).
