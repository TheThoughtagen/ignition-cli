<objective>
Finish the DeployApi surface with deployment modes (DAPI-05), close the endpoint table so every method has exactly one declared, capture-backed shape (DAPI-06), and build the one stateful fake gateway that later phases test against.

Purpose: `deployment_mode()` is how Phases 22-24 check that a node is actually running the target mode, so `null` and `""` must both read as "no mode". The 20-01 C-null capture decides whether the gateway sends null, `""`, an absent key or something else. The fake makes Phase 23's apply engine testable without a gateway. To stop it from encoding assumptions as facts, it calls the library's own pure verdict functions, and 20-06 runs one shared scenario against it and against the live gateway and compares the traces.

Decision noted here: `deployment_mode()` returns `Option<String>` (research A6, a discretion area) rather than the `""` sentinel in milestone SUMMARY Conflict 10. Both carry the same intent, that null and `""` both mean no mode. Phase 22 compares the Option against the target.

Output: `client/mode.rs`, three trait methods, the endpoint-closure test, `tests/common/fake_deploy.rs` and `tests/common/deploy_scenario.rs`.
</objective>
