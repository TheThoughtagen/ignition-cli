    - `restart_and_wait(api, interval, timeout) -> RestartWaitResult` — POST → **tokio sleep 5s floor** (Open Question 4 mitigation: a fast restart could flip back to RUNNING before the first poll observes STARTING; treating post-floor RUNNING as success closes the race) → poll `status_ping` until `state == "RUNNING"` (STARTING/unknown = Pending with the observed state as last-observation).     - `wait_module(api, module_id, interval, timeout)` — poll `modules(healthy, search=module_id)` until an item with `state == "ACTIVE"` (Pending otherwise; deadline names last observed state).
    - Defaults: interval 2s; timeout 300s (restart) / 120s (gateway, module) — research §Wait-loop pattern.

    - wait timeout: StatusPing always STARTING with deadline 1s → Network-class error whose message contains "STARTING".
    - wait_module: modules list with the target module ACTIVE → Ok; missing module → timeout naming the id.
