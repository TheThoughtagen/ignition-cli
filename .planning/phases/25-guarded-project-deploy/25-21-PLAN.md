- fixes the IN-01 and IN-03 docs;

## Decisions carried into this plan

- **Add-Type is kept (the bounded evaluation asked for by G-25-5).** A `DefinePInvokeMethod` declaration would need `DefineDynamicAssembly`, `DefineDynamicModule`, `DefineType`, `DefinePInvokeMethod` and `CreateType`. It would also need a `CustomAttributeBuilder` that sets `DllImportAttribute.SetLastError`; without it `GetLastWin32Error` is unreliable and the 32/5 retry classification breaks silently. That route is not cheap:
  - None of it can be exercised offline. The local pwsh crashes, and pwsh 7 runs on a different .NET runtime from Windows PowerShell 5.1, so an offline run would not prove the target anyway.
  - Any mechanism change would rest its whole atomicity proof on the 11-minute 25-20 race gate, whose shipped `replace_ok` cleared its floor by 18, so a rerun can stop on `gate throughput:` for reasons unrelated to correctness. This plan also reruns that gate, but only as a regression check on a text change. The MoveFileEx mechanism it exercises is the one 25-20 already proved.
  
  It is not clearly safe either. In-memory P/Invoke through Reflection.Emit is the technique of offensive PowerShell tooling (PSReflect style). On the hardened hosts WR-01 is about, it trades the csc/TEMP dependency for an AMSI/EDR one that the capture host cannot show. The cost it would save is paid once per record write (one per deployed project per run), not per file. Decision: keep Add-Type and record the cost. The cost is the 2.70 s fresh-process replace measured in 25-20, plus this plan's baseline-versus-record_replace medians from the preflight. The prerequisites go in the README. Rated reversible: the declaration lives in one fixed const behind `WinScript::record_replace`.
- **Cause channel.** The cause rides the thrown text. The success and failure contract of `interpret_output` stays as it is, and no Rust error path or slug changes. PowerShell 5.1 wraps error lines at 119 columns. The tail keeps 5 lines, and a thrown string ends its record with `FullyQualifiedErrorId : <thrown text>`. Each thrown text is therefore held to 300 characters, so its FullyQualifiedErrorId chunks (at most 3) and CategoryInfo fit in the tail whole. Tests compare with all whitespace removed, because a wrap can fall anywhere and `clixml_errors` trims each chunk.
- **Path redaction.** The detail already carries the home-relative location `~/ign-deploy/...` and the node label, never a native account-home path. The cause replaces every drive-letter or UNC path with `<path>`, the same idea as `scrub_stderr`'s `<tmp>`.
- **The race gate is re-run, unchanged.** The MoveFileEx call, the flags, the guard and the retry loop are byte-identical (Task 1 pins the segments), but the shipped text changes: two new function definitions, a new FullLanguage throw text and two new failure throws. The race writer runs the bytes of `winps::RECORD_REPLACE` in-process, and in 25-20, 34 of 352 shipped attempts took a failure branch, so the race exercises the new text on the very path this plan changes. Task 4 therefore re-runs `wflwvm01_record_replace_race` exactly as it is, after the preflight and before the two new live tests, under the 25-20 rules:
  - `Pass` (the test passes): continue to the new tests.
  - A `gate throughput:` panic (torn, missing and backwards all 0, but a count floor still missed at the fallback constants): the fix is not shown failed, the gate was too thin. STOP and report a gate-throughput gap.
  - A `fix failed:` panic (any torn, missing or backwards read on the shipped run, or an insensitive negative control): STOP and report a failed-fix gap.

  No constant, floor, calibration rule or harness body changes, and nothing is retried beyond the gate's own single fallback rerun. The rerun must pass for the checkpoint to be approved. It took 685.98 s at the fallback constants in 25-20; allow up to about 15 minutes. The fresh-process preflight still runs first, because it proves the changed text parses and succeeds on PowerShell 5.1 in the route the writer uses.
- **Offline proof of the CLIXML shape.** The cause-survival test and the writer mock test both rely on `ps51_error_clixml`, so the builder itself is checked against captured bytes. Its fixtures are 22-LIVE-CAPTURES.md lines 4751-4752, 4767-4768 and 7223, copied byte for byte. The test proves the framing, the position-independent chunks of a thrown string, the 119-column message wrap, the wrapped `+` line and the target ellipsis. No capture shows a FullyQualifiedErrorId line longer than one 114-character piece (the captured chunks are 34 and 90 characters), so that part of the builder stays a model. The live Add-Type cause test in Task 4 is its proof: its thrown text is about 250 characters, so its FullyQualifiedErrorId line spans three pieces on real PowerShell 5.1.
- **No new CoreError slug or exit code.** A blocked or impossible replace stays `transport_failed` (exit 4). After a verified import, a failed record write stays `record_written: false` plus a warning.
