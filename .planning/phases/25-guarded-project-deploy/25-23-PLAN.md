<objective>
Close G-25-10: ign must restrict the ssh key file to its owner when the Actions runner service runs under a Windows service account.

Today `restrict_to_owner` in remote.rs grants the key file to the account name read from the user-name environment variable. Under NETWORK SERVICE, the runner's default account, that name is the machine account (`ignwin836$`). icacls cannot map it (error 1332), so the check job fails with transport_failed before ssh runs. `harden_dir` in run_store.rs uses the same lookup for the apply's run directory, so an apply would fail the same way next.

This plan adds one small module that reads the current process's SID from whoami.exe and grants by `*SID`, then routes both call sites through it. It stays fail-closed and adds no dependency.

Purpose: the check's `.git` probe and release-record read (DPRJ-04, DPRJ-05) and the apply's export, import and record write (DPRJ-03) all run over ssh with this key, and the apply writes its run directory under the same account.
Output: `deploy/owner_acl.rs` with offline tests, and both call sites moved to it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI secret (key text) → key file on the runner disk | The private key lands in a temp file that other local accounts and services must not read |
