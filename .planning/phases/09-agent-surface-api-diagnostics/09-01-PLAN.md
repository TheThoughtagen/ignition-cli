1. New variant in `CoreError` (after `LintToolAbsent`, error.rs:443), modeled on 09-RESEARCH.md Pattern 1:
   ```rust
   /// The gateway answered the api call with a 4xx this CLI does not
   /// curate — the caller's request is the problem, and the body is
   /// theirs to read. Exit 2 (usage class; additive slug — the
   /// poll_interval_too_small precedent: same class, own slug, no new
   /// exit code).
   #[error("gateway rejected the api call (HTTP {status} from {endpoint}): {body}")]
   GatewayClientError {
       /// HTTP status the gateway answered with.
       status: u16,
       /// Full URL of the rejected request.
       endpoint: String,
       /// The response body VERBATIM, truncated at
       /// [`GATEWAY_CLIENT_BODY_CAP_BYTES`] with an explicit marker.
       body: String,
   },
   ```
2. Beside the variant, the contract cap: `pub const GATEWAY_CLIENT_BODY_CAP_BYTES: usize = 4096;` plus `pub const GATEWAY_CLIENT_BODY_TRUNCATION_MARKER: &str = "... [truncated]";` — the marker is ASCII-pinned (golden-safe). The cap is applied at CONSTRUCTION (Task 2's classify arm), so the variant always carries its final form; a unit test in error.rs pins `truncates_at_cap_with_marker` (build the variant via a small helper `truncate_api_body(body: &str) -> String` defined beside the consts so construction cannot forget it).
3. `code()` arm => `"gateway_client_error"`; `exit_code()` arm => add the variant to the exit-2 group (`ConfirmationRequired | InvalidImportFile | InvalidInput | GatewayClientError`); `hint()` arm => actionable, e.g. "the gateway rejected this request — the body above is the gateway's own answer; fix the path/method/body, or use a curated `ign` command when one exists".
