<objective>
Let a user roll a past run back from a fresh process with only the target file and the run id, refusing when live state has moved on since that run unless they explicitly discard it.

Purpose: DAPL-08 and D-07. The on-box record written by apply (23-03, 23-05) makes the rollback independent of the runner that applied; the one `restore_snapshot` from 23-17 does the work.
Output: `run_rollback`, `deploy_rollback_prepare`, `deploy_rollback_execute`, `DeployRollbackResult`, `rollback_` tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `--run` text → on-box paths | A user-supplied id selects which snapshot overwrites the live collection |
| on-box record → restore set | A file on the host decides what is written back |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-45 | Tampering | path traversal via `--run` | high | mitigate | `RunId::parse` before any path is built; test `rollback_bad_run_id_is_invalid_input` (canon path-traversal: breadcrumb to /gsd-secure-phase) |
| T-23-46 | Tampering | rollback silently overwriting newer live work | high | mitigate | Touched-set staleness against `post_fingerprint`; `deploy_live_changed` unless `--discard-live-changes`, which is recorded |
| T-23-47 | Tampering | a forged or foreign record steering the restore | high | mitigate | Strict `RunRecord::parse` with gateway and mode match; local run-dir cross-check when present |
| T-23-48 | Repudiation | who rolled back and what was discarded | medium | mitigate | Rollback run directory, `rolled_back_by` in the on-box record, discarded paths in `run.json` and events |
</threat_model>
