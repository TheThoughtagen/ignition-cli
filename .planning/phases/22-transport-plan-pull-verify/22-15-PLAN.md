<objective>
Close UAT gap G-22-2: a tree made by `ign deploy pull` must verify green against the gateway it was pulled from. Today `read_back` drops JSON-null members from the file config only (N1, one-sided) and compares against the raw REST config. Ignition 8.3.6 reports `ignition/cobranding`'s nine unset image fields as explicit `null` in REST, the same nulls the pulled file holds. After the one-sided strip those keys exist only on the REST side, so every default-branded gateway's pull comes back red.

Purpose: make N1 symmetric (null equals absent on both sides) without masking a real difference. Pin it with regression tests at the engine, action and binary levels, correct the three documents that state the one-sided rule, and prove pull then verify green on the live rig. Before UAT, the live verify had only ever run on the two-resource tracer tree, never on a pulled one.
Output: the fixed `verify.rs`, regression tests in `deploy_verify.rs` and `contract_deploy.rs`, the live test `pull_then_verify_is_green_live`, and updated README and CV2 decision text.
</objective>
