       ```rust
       if let Commands::Mcp(args) = cli.command {
           let profile_flag = cli.profile.clone();
           return runtime.block_on(mcp::serve(args, profile_flag.as_deref(), &runtime));

       ```
       Pass `profile_flag.as_deref()` — the outer Cli already ran apply_env_defaults, so IGNITION_PROFILE is folded ONCE in the one env-to-flag home (CORE-09). The inner dispatch re-injects this flag; it must NEVER inherit outer `cli.yes`.
    2. **mcp.rs serve loop** (research Pattern 2 skeleton): tokio `BufReader::new(stdin()).lines()` reader; `tokio::sync::mpsc::unbounded_channel::<String>()` + ONE spawned writer task as the sole stdout owner, writing `serde_json::to_string` per message — COMPACT ONLY (never `to_string_pretty`: embedded newlines are a spec violation and a protocol death). Message handling:
       - `initialize` → result `{ protocolVersion: <negotiated>, capabilities: { tools: {} }, serverInfo: { name: "ign", version: env!("CARGO_PKG_VERSION") } }`; negotiation per spec: requested == "2025-06-18" → echo it, otherwise respond "2025-06-18" (single supported revision; OQ5 planner-locked pin).
       - `notifications/initialized` (and any notification without id) → no-op, no response.
       - `ping` → respond `result: {}` INLINE on the reader path — never queued (the SC-5 starvation constraint).
       - `tools/list` → respond the Task-1 catalog (`{ tools: [...] }`), ignore any cursor param gracefully.
       - `tools/call` → `tokio::spawn` the execution; route the rendered response through the mpsc to the writer. Out-of-order responses are legal (JSON-RPC id matching) and are what make ping non-starving true by construction.
       - unknown method WITH id → JSON-RPC error `-32601`; unparseable line WITH recoverable id → `-32602`; malformed request without an id → log to stderr (tracing), keep serving. NEVER `std::process::exit` or `e.exit()` mid-protocol.
    3. **dispatch bridge `execute(call) -> (String, bool)`** (research Pattern 3 sketch):
       - argv = `["ign"]` + tool path segments + flag tokens from arguments (property name = the clap long name / positional id — map 1:1 to tokens); if `confirm == Some(true)` push `--yes`.
       - `Cli::try_parse_from(argv)` → `Err(e)` → return a `-32602` JSON-RPC error response carrying `e.to_string()` — NEVER `e.exit()` (Anti-Pattern: clap would print usage and kill the process).
       - On `Ok(mut inner)`: set `inner.profile = profile_flag.map(...)` (ambient-resolved profile rides in), `inner.json = false; inner.compact = false;` and leave `inner.yes` exactly as parsed from argv (only `confirm:true` produced `--yes`) — apply_env_defaults is BYPASSED here so IGNITION_YES in an agent's shell can never confirm a write (SC-2 verbatim; research Anti-Pattern 3).
       - `let mode = RenderMode::resolve(true, true)` (compact-json); `let (profile, result) = runtime_handle.block_on(dispatch(inner, mode));`
       - Success: `out.render_json(profile.as_deref(), true)` (main.rs:298). Error: `serde_json::to_string(&err.envelope(profile.as_deref()))` (error.rs:935). Add a unit test pinning BOTH serializations byte-equal to what `render_ok`/`render_error` write in CompactJson mode for the same inputs — the envelope passthrough must be FROZEN-verbatim, not re-shaped.
       - `isError` = parse the envelope string and check `json["ok"] == false` (spec: business-logic errors ride isError, not protocol errors).
    4. Anti-sabotage: comment out the writer-task spawn → a hand-run `echo '{"jsonrpc":"2.0","id":1,"method":"ping"}' | ign mcp serve` shows no response → restore. (Full protocol coverage is 14-02's contract suite.)
