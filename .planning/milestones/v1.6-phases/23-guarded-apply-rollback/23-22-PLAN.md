<objective>
Close G1 (UAT test 2, FA-23-05). The POSIX sftp listing parser (`ListFormat::Prefixed`, phase 22 commit 72b2d34) finds each line's directory by the `<dir>/<name>` prefix. That prefix exists only when the sftp CLIENT formats the line itself. In openssh-portable `sftp.c` `do_ls_dir`, the client calls `ls_file(fname, ...)` with the full path when `-n`/`-h` is given or the server offers `users-groups-by-id@openssh.com`; otherwise it prints the server's `longname`, which is a bare name. The macOS `sftp-server` offers the extension, so every local test saw prefixed lines. Ubuntu 22.04's OpenSSH 8.9p1 server does not, and neither does the Win32-OpenSSH server seen so far, so every listing on ign-lnx-836 failed at the first line (`.`).

Purpose: one listing format for every host. Each `@ls -la` gets an `@pwd` marker, as Windows already has (22-13). The name may be bare or carry the listed-directory prefix, so the read half, `prepare` and `ign deploy plan` work on a real Ubuntu ssh node. Then the four FA-23-05 gates run again, and the README stops calling the Linux host unproven.
Output: the parser change with regression tests from two real captures, a read-only capture gate, the four gates passing on ign-lnx-836 and recorded, and the README sentence with its coverage needle.
</objective>
