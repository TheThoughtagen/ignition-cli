<objective>
Close the engine half of G2 (UAT test 5). On windows-latest, 18 `deploy_host_conformance` tests fail in `prepare` with `remote mkdir "/C:/Users/RUNNER~1": Failure`, labelled "(refused with no reason: a held or non-empty target)". The hypothesis, to be confirmed first: `put_tree` surveys the staging root from the drive root (`/C:`) down. The runner's temp dir, which the PowerShell rows use as data dir and account home, is spelled with the 8.3 short name `RUNNER~1`. The listing of `/C:/Users` shows only the long name, so the survey thinks the short-named component is missing and asks the server to create a directory that exists, and the server answers `Failure`.

Purpose: confirm that cause on the Azure VM with an 8.3 spelling of the real account home, then fix it in the engine. A staging root below the account home is surveyed from the home, as every read below the home already is (`read_journal`, `read_record`, `fetch_snapshot` descend from it), and a failed `mkdir` gets an honest description. Decision: engine fix, not a test-only change. An account home spelled in 8.3 form fails every Windows prepare the same way. The drive-root survey also lists every ancestor of the home, which a hardened host may deny. And canonicalising the test's temp dir would hide the case on the one runner that exercises it.
Output: root-cause record, `survey_root`, the mkdir class text, the short-name live gate, offline tests, and a Windows rehearsal of the CI leg on the VM.
</objective>
