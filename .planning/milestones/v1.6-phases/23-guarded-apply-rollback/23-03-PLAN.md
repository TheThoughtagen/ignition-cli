<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run directory → git | Files holding secrets sit inside the user's repo |
| on-box journal and record → any later runner | A file on the gateway host steers recovery and rollback |
| run id text → filesystem paths | A run id becomes a local and an on-box path component |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-09 | Information disclosure | run directory committed to git | high | mitigate | `ignore_status` before any write; `NotIgnored` and `GitUnavailable` refuse; 0700/0600 and an owner-only ACL on Windows |
| T-23-10 | Tampering | path traversal through a run id (`../x`) | high | mitigate | `RunId::parse` enforces `[A-Za-z0-9._-]{1,128}` with no leading dot before any path is built (canon path-traversal: breadcrumb to /gsd-secure-phase) |
| T-23-11 | Tampering | forged or corrupt journal or record steering a restore | high | mitigate | Strict parse (caps, duplicate keys, unknown fields, gateway and mode match, path rules); refusal names the location; no fallback to a default |
| T-23-12 | Denial of service | oversized or deep on-box JSON | medium | mitigate | 8 MiB cap before parsing; `node::classify` depth and duplicate-key hardening |
| T-23-13 | Information disclosure | events log content | medium | mitigate | `EventLog` takes value-free fields only (paths, hashes, ids, counts); the canary in 23-15 scans it |
