<objective>
Give the library read and write access to config resources by type and name, from the effective view or from a named collection, with a typed error for a stale or missing signature.

Purpose: covers DAPI-01 and DAPI-02, plus DAPI-06's cap on the classify 422 echo.

DAPI-02 (amended 2026-10-12; REQUIREMENTS.md and ROADMAP Phase 20 SC1): "create config resources by POST and update them with the signature-checked array PUT; a stale or missing signature surfaces as its own error". `resource_create` is the POST create. `resource_update` is the signature-checked array PUT: an array body with a signature on every item. The amended text rests on the OpenAPI (PUT modifies with name and signature required, POST creates with name only) and on the v1.1 capture of a PUT of an unknown name answering 404. Capture C3a (its PUT-unknown-name sub-block, Decision D10) is the 8.3.6 confirmation, recorded in the SUMMARY.

The stale-signature mapping lives in `deploy_api.rs`, not `classify.rs`. Putting it in classify would flip the v1.1 pin `task_delete_signature_mismatch_500_is_the_recorded_finding` (exit 1 `internal`).

Output: `client/config_resources.rs`, six new `DeployApi` methods, the deploy-scoped write guard, and the capped 422 echo.
</objective>
