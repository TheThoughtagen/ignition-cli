<objective>
Close G-25-13 (the blocker) and G-25-9.

G-25-13: GitHub delivers a caller's environment secrets to a reusable workflow's environment job only with `secrets: inherit`, and `secrets: inherit` works only inside one organization or enterprise. This is from the probe in WhiskeyHouse/whk-ign-deploy-uat, env uat-probe. With an explicit mapping, or none, the secret is empty whether or not the workflow declares it. With `secrets: inherit` it is present. Cross-org (a TheThoughtagen workflow called by a WhiskeyHouse caller, run 40698754776), `secrets: inherit` passes nothing. The UAT apply therefore saw empty IGN_MASTER_TOKEN and IGN_SSH_KEY. Per owner decision O3 (2026-10-28), the check and apply step logic moves into two composite actions in this public repository. A caller in any organization then owns both jobs, and its apply job's `environment:` resolves the environment secrets natively. deploy-projects.yml stays for same-organization callers, runs the same actions from its own commit, and fails with a message naming the cause when the write secrets are empty.

G-25-9: Git for Windows sets `core.autocrlf=true` in the system gitconfig. actions/checkout honours it, the targets checkout got CRLF, and ign refused the tree (deploy_tree_invalid, carriage return). Every checkout, and every git or ign step, now disables autocrlf for itself through the git environment config.

Purpose: the approved apply deploys exactly the checked artifact_sha256 (DPRJ-01) at the checked targets commit, and only the approved job holds write secrets while the unapproved check (DPRJ-05) holds read-only ones, from a caller in any organization. This keeps D-02 (per-environment jobs gated by environment protection), D-07 (read-only sparse targets checkout without credentials) and D-15 (the reusable deploy-projects.yml).
Output: the two action.yml files, the rewired deploy-projects.yml, and the harness extended to them.
</objective>
