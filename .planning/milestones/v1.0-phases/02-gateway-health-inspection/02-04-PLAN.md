    **poll.rs (new, core lib — registered in lib.rs):** the ONE wait/retry engine (research §Wait-loop pattern; ~30 lines + tests — no retry framework, reqwest-middleware was rejected in STACK.md):
    - `pub struct PollConfig { interval: Duration (default 2s), max: Duration (clamp ceiling 30s), deadline: Duration }` with adaptive growth ×1.5 clamped to [interval, 30s].
    - `pub async fn poll<T, F, Fut>(cfg: PollConfig, probe: F) -> Result<T, CoreError>` where `F: FnMut() -> Fut`, `Fut: Future<Output = Result<PollState<T>, CoreError>>` and `PollState<T> = Done(T) | Pending(Option<String> last-observation)`.
    - Semantics: `CoreError::Network` and `GatewayRestarting` are retried (transient); **Auth is NEVER retried** (fail fast); any other error aborts; deadline expiry → `CoreError::Network`-class error carrying the last observation in the message (exit 4 — research: "deadline expiry → Network-class timeout error"; reuse the network_error slug, no new variant).
    - Unit tests with a scripted FakeProbe: success-first-poll, retry-then-done, auth-fails-immediately, deadline-expiry message, backoff-sequence math (2s,3s,4.5s,…clamped 30s).

    **actions/logs.rs — tail loop (starts here; Task 3 wires the command):**
    - `tail(api, filters, interval, deadline: Option<Duration>) -> TailResult` — cursor starts at `now - since` (or 0); loop via poll: each iteration `logs(LogQuery { start_time: cursor+1, .. })`, print/collect new entries in timestamp order, advance cursor to max timestamp seen; empty page → Pending. `deadline: None` = run until Ctrl-C (process default kill — research: keep Ctrl-C simple, document); `Some(d)` = graceful end → `Ok` (tail ends cleanly, exit 0 — entries already streamed).
    - The action RETURNS streamed lines in a `Vec<LogEntry>` for testability while the dispatch prints incrementally — OR (simpler, preferred): tail takes a `sink: &mut dyn FnMut(&LogEntry)` so dispatch streams and tests capture. Pick the sink design; keep the action printer-free.
