<decisions>
Taken at planning. They are not open questions. If one proves wrong, stop and report it.

**D1. The tree read is the native REST export:** `GET /data/api/v1/tags/export?provider=<P>&type=json`, one call per provider, plus the existing provider list (`GatewayApi::tag_provider_list`). The WebDev `tagConfig` route refuses a provider root (`provider_root_unsupported`) and needs a deployed route. The host tree holds UDT instances without members and adds host permissions and a collection merge. The native route needs neither and is what the deploy read-back tests already use.

**D2. Expansion, as captured on 8.3.6:** the export wraps the provider as `{"name":"","tagType":"Provider","tags":[...]}`, holds types under a `_types_` Folder child, and gives an instance one stub per direct member: `{"name":"RInst","tagType":"UdtInstance","typeId":"A/B/T","tags":[{"name":"M1","tagType":"AtomicTag"}]}`. Stubs for nested instances and inherited types were not captured, so the lookup treats stubs as optional and always also resolves `typeId` through `_types_`.

**D3. Lookup has three answers:** `Found`, `Missing`, `Unknown`. `Unknown` (an unresolvable `typeId`, a `typeId` naming another provider, a cycle, or the chain guard tripped) is never reported. A false "missing" is worse than a miss here, because this feature exists to be read and believed.

**D4. JSON contract.** New keys, placed after `children` and before `outcome`, following the `children` precedent:

| Situation | `missing_tags` | `missing_tags_count` | `missing_tags_unavailable` |
|---|---|---|---|
| No reference, or none on a readable provider | `[]` | `0` | `null` |
| Every needed provider read | list | n | `null` |
| Some providers read | list for those read | n | `[{provider, reason}, ...]` |
| Nothing read (list failed, or every export failed) | `null` | `null` | `[{provider, reason}, ...]` |

- `missing_tags_unknown_providers` holds the references D8 classes as unknown, in every row of the table: `[]` when there are none, `null` only when the provider list itself could not be read. Each entry is `{provider, path_count, files}`, where `path_count` counts distinct paths after property stripping and letter-case folding, and `files` holds at most 3 byte-sorted members. One entry per ASCII-folded name, byte-sorted by provider, capped at `LIST_CAP` with `missing_tags_unknown_providers_count` beside it.
- `missing_tags_limit` is always the constant `MISSING_TAGS_LIMIT`.
- Each `missing_tags` entry is `{path, files}`. The list is byte-sorted and capped at `LIST_CAP`, with the full count beside it, as every list in this result is.
- `provider` is `null` when the failure is not per provider.
- `reason` is fixed wording plus `err.code()`. It never carries a response body.
- `null` rather than `[]` when nothing was read, because an empty list reads as "no missing tags".

**D5. Matching:** a provider folds ASCII case, as `deploy/exclude.rs` does. A tag path folds with `to_lowercase()`. A wrong-case reference is therefore not reported, which is the safe direction.

**D6. What is read and scanned:**
- Scan the artifact zip, not the repo, so only what would be imported counts.
- Scan `*.py` everywhere (this covers `ignition/script-python`, `ignition/timer/<name>/handleTimerEvent.py`, `ignition/tag-change/<name>/onTagChange.py`, `ignition/scheduled`, `ignition/update/onUpdate.py` and WebDev handlers) and `*.json` except `resource.json` and the root `project.json`.
- Skip any member with a directory component exactly `__tests__`, for both `missing_tags` and `missing_tags_unknown_providers`. Test packages hold fixture-style names such as `[TEST]Fake/...`. A local project checkout has 45 such folders under `ignition/script-python`. State this in the limit text.
- Binary resources are not read. `ignition/event-scripts/data.bin` is a gzip of a binary container on a production-shape project checkout, and reading it would add a dependency. State this in the limit text.

**D7. A reference is an anchored literal, never free text:**
- In Python it is a whole string literal.
- In JSON it is a whole string value, a `{[p]path}` expression reference, or a quoted `'[p]path'` / `"[p]path"` inside an expression.
- A label such as `see [default]A/B` is not a reference.

**D8. Providers (revised by the team lead: a provider the target lacks must not pass as clean).** Each reference falls in one of four classes, tested in this order after the one provider list:
1. **Excluded** (`exclude::effective(&loaded.target, None)`, matched with `exclude::is_excluded`): never exported, never reported. This keeps `[System]...` and generated providers out and avoids their export cost.
2. **Listed:** one export, then lookup. A listed provider whose export fails is "a provider that's absent" (brief item 4) and goes to `missing_tags_unavailable`, never to `missing_tags_unknown_providers`.
3. **Unlisted and provider-shaped:** reported in `missing_tags_unknown_providers`. No export call, and never in `missing_tags`.
4. **Unlisted and not provider-shaped:** not a provider reference, dropped.

A name is provider-shaped when it holds at least one letter, holds only letters, digits, `_`, `-` and inner spaces, and is not `client`. The rule runs at this step and not in `parse_literal`, so a listed provider with an unusual name still matches exactly.

Calibrated read-only on a local project checkout, the rule removes `[.]` (272 uses), `[0].x` (28), `[~]` (9), `[%s]`, `[<name>]` and `[a, b]`. `[client]` is Vision's project-scoped client tag prefix, not a gateway provider. `[ERROR] text` never gets here because `parse_literal` refuses a leading space. A docstring example such as `[provider]Area/MES/SomeData` never gets here because the lexer skips it. The same text in an ordinary string is reported as one entry for a provider named `provider`, which is accepted as warning-only noise.

**D9. No new dependency.** Hand-written linear lexers, no regex.
</decisions>
