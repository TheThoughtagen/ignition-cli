# Quick 261105-cr1: PR #39 Windows CI fix and CodeRabbit review

Each item is checked against the code before it is changed
(superpowers:receiving-code-review). An item that is wrong is pushed back
in the SUMMARY with the reason.

## Tasks

- **C0 (CI).** `bundle::tests::extract_round_trips_an_honest_archive` asserts
  that the zip crate writes host 3 with mode `0o100644`. On Windows the crate
  writes host 0 (zip 8.6 `types.rs`: `cfg!(windows)` picks `System::Dos`
  unless the options name a system). Make the test build the Unix-made shape
  it documents on every platform: pin `System::Unix` instead of a cfg branch.
  Grep the other zip-writing tests for the same assumption.
- **C1.** `central_records` reads from the central-directory start to EOF
  into one `Vec`. Walk the records one at a time through a buffered reader
  and stop at `READ_MAX_ENTRIES + 1` records. RED: a crafted archive whose
  records sit at offset 0 with 8 MiB after them, read through a counting
  reader. The walk may read only a small bound.
- **C2.** BUNDLE reads each source to EOF before it compares the bytes with
  the listed size. Cap each read at the bytes still allowed (listed size
  plus one), so a growing file stops at `n + 1` bytes. Use only PS 5.1
  constructs: no `[Math]::Min`, no new overloads. `sftp.rs` names an
  over-size answer as "more than its listed size". RED: a pwsh row where a
  300,000-byte file is listed at 70,000 bytes answers `n = 70001`.
- **C3 (live, compile-checked only).** Before any `az vm run-command` call
  in the seed and restore gates, compare `[Environment]::MachineName` over
  ssh with the same name read through the az route. Refuse when they differ.
  The admin functions take a value that only the check can build.
- **C4 (live, compile-checked only).** In the restore branch "nothing to
  restore", remove a partial `ign-prod-shape` work dir: one with no manifest,
  which means nothing was seeded.
- **C5.** README: the cleanup sentence names the outcome where BUNDLE_CLEAN
  fails too.
