# Quick 261030-8m8 Plan 01: Lift the CD5 refusals of root-level tags and nested UDT folders Summary

**`ign deploy` now pulls, plans, applies and verifies root-level tags (CD5a) and nested UDT type folders (CD5b). A two-host live capture (Docker 8.3.6 and the Windows VM over sftp) showed that both layouts take a file-level write, change and delete in one config scan. Render now refuses tag markers whose `files` list disagrees with the member files (CD5c) and tag folders named like a member file (CD5d).**

This unblocks the 79 units that `ign deploy pull --env production` against WIGNVM01 skipped as `render_refused` on 2026-10-29: root-level tags in `default`, `Gateway` and `Spark`, and 76 nested `tag-type-definition` folders. Production itself was not touched.

## Decision-table rows applied (Task 2)

- **CD5a accept:** the root-level `if` in `layout::tag_collection_path` is gone. `tags/<P>/tag-definition/{tags,udts}.json` maps to `ignition/tag-definition/<P>/...`.

- **CD5d accepted:** render refuses a tag folder component named `tags.json`, `udts.json` or `unary-resource.json`, compared with ASCII case folding.
- **Docs in code:** `collection_path` and `repo_path` cite CD5a/CD5b, and the old `repo_path` refusal caveat is removed. The render module doc cites CD5a..CD5d. A non-default collection is still the one unexercised layout.
