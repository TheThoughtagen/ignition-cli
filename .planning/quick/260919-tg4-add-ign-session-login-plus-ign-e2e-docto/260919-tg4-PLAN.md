<objective>
Add three verbs: `ign session login` (expose the native IdP session the
trial-reset ladder and `ign adopt` already perform, in a shape a Playwright
`globalSetup` can consume verbatim), and `ign e2e doctor` / `ign e2e init` —
the browser-E2E scaffold pair. `ign e2e run` is deliberately NOT in scope:
the scaffold's own `npm test` is the runner.

Purpose: an agent or a developer can go from a bare commissioned gateway to a
green Playwright run without opening a browser to log in, and without
hand-writing the auth bootstrap that every Ignition E2E suite otherwise
reinvents.

Output: two new core action modules, one embedded template tree, two contract
test files, three clap leaves wired through dispatch + human render + the TUI
registry, one new error variant, and the README rows that document all of it.

<planner_decisions>

Where the spec said "decide", this plan decided. The executor implements these
as written and does not re-litigate them.

**D1 — Chromium presence check is the browsers-cache directory, not `npx playwright install --dry-run`.**
`npx` on a host without the package cached will reach for the registry, which
breaks the doctor's offline/read-only posture and its "exit 0 whenever the
diagnosis completes" contract; `--dry-run` output is also not a stable
contract. The check is pure filesystem: `PLAYWRIGHT_BROWSERS_PATH` when set,
else `~/Library/Caches/ms-playwright` (macOS), `~/.cache/ms-playwright`
(Linux), `%LOCALAPPDATA%\ms-playwright` (Windows). `ok` when any directory
entry name starts with `chromium-` or `chromium_headless_shell-`; `warn`
otherwise (a missing browser is fixable, not a failure state).

**D2 — TLS relaxation: no new npm dependency. `lib/gateway.mjs` sets `NODE_TLS_REJECT_UNAUTHORIZED` to the string `0` at module load, guarded by the SAME localhost rule the Playwright config uses, and warns once on stderr when it does.**
`undici` is rejected: adding a transitive HTTP stack to a scaffold whose only
job is three `fetch` calls is exactly the framework creep the project
constraints forbid. The guard is `host in {localhost, 127.0.0.1, ::1}` OR
`IGNITION_ALLOW_INSECURE_LOCAL === 'true'` — one rule, two consumers
(`playwright.config.mjs`'s `ignoreHTTPSErrors` and `gateway.mjs`), so they
cannot drift. The generated `README.md` names `NODE_EXTRA_CA_CERTS` as the
correct path for a remote gateway behind a private CA.

**D3 — `--yes` gate, and it gates the WHOLE verb (the preview doubles as the dry run).**
Consistent with `rig trial reset` / `project delete`. Without `--yes`,
`ign e2e init` writes nothing and spawns nothing: it computes the member list
and the command list, then refuses exit 2 `confirmation_required` with both
inside `CoreError::ConfirmationRequired`'s `operation` string. No separate
`--dry-run` flag is added — the refusal IS the preview, and one gate is
simpler than two flags.

Three mechanical facts (verified in the tree) constrain HOW this lands:
`--yes`/`-y` is a **GLOBAL** clap arg (`cli.rs` line 35), so `E2eCmd::Init`
declares NO `yes` field of its own; `IGNITION_YES=1` is already merged into
`cli.yes` by `apply_env_defaults` (`main.rs` line 3148), so neither the action
nor the dispatch arm reads that variable; and the guard MUST be a
`require_confirmation(cli.yes, …)` call in the **dispatch arm** plus a
`GUARDED_OPS` registry entry, because
`main.rs::tests::guarded_ops_registry_tracks_every_dispatch_site` walks the
dispatch sites and the registry in both directions and the MCP catalog derives
its synthetic required `confirm` property from `GUARDED_OPS` alone (SC-2).
The dynamic preview is therefore built by a separate
`e2e_init_preview(...) -> Result<String, CoreError>` the dispatch arm calls
BEFORE `require_confirmation`, so the foreign-directory and node refusals win
over the confirmation refusal and the preview text is accurate.

**D4 — Node-missing is exit 6 `node_tool_absent`, not exit 7. THIS DEVIATES FROM THE SPEC LINE AND IS DELIBERATE.**
Exit 7 in this repo is the `rig` class whose SOLE slug is `rig_error`
("docker/compose rig failure (discovery, lifecycle, port conflicts)" in the
machine-checked README table). Putting a missing Node there would force a
relabel of a locked exit class. The spec's own rationale — "the exit class for
a missing host tool" — is already served at exit 6 by `lint_tool_absent`,
which is the exact same shape: a local external tool a verb delegates to is
absent, with an install hint. So: new variant
`CoreError::NodeToolAbsent { tool: String }` → exit 6, slug `node_tool_absent`,
mirroring `LintToolAbsent` line for line. Flipping it to 7 later is a
one-line move plus a README row.

**D5 — `ign session login` human render is pinned by a PURE FUNCTION, not by stdout capture.**
`render.rs` renders with `println!`, which no unit test can read. The render
arm calls `pub(crate) fn session_login_human_lines(result: &SessionLoginResult) -> Vec<String>`
and prints them; the unit test asserts over the returned lines. Precedent:
`to_junit_xml` / `to_console` in `actions/testing.rs`.

**D6 — `--user` resolution order is flag → `IGNITION_USER` → `admin`.**
`adopt` uses flag → `admin`; `rig trial reset` uses flag → `IGNITION_USER`.
The spec asks for both, so this verb takes the union.

**D7 — Playwright cookie `domain` is the profile URL's HOST WITHOUT the port, `path` is `/`.**
Playwright's `storageState` cookie shape rejects a port inside `domain`.
`secure` is `true` only when the profile URL scheme is `https`; `httpOnly` is
`true` and `sameSite` is `Strict` (matching the gateway's real `Set-Cookie`
attributes documented in `idp.rs`); `expires` is `-1` (a session cookie).

**D8 — `e2e init --project` defaults to `ign-cli`; `--run-project` defaults to the effective `--project`.**
`ign-cli` is the CLI's own WebDev project — the same default `ign script run`
and `ign doctor --webdev-route` already use. `e2e doctor --project` stays
OPTIONAL with NO default (per spec, the gateway rows `skip` without it).

**D9 — Template sources on disk all carry a `.tmpl` suffix.**
A literal `.gitignore` inside `crates/ignition-core/e2e-template/` would be
honored by git against its own siblings, and a literal `package.json` there
would be picked up by any npm workspace scan. One uniform rule — every source
file is `<written-name>.tmpl`, with `gitignore.tmpl` mapping to `.gitignore` —
avoids both hazards, and a test pins that no member path reaches disk with a
`.tmpl` suffix.

**D10 — Environment injection instead of `std::env::set_var` in tests.**
Both e2e actions take `&E2eEnv { path: Option<OsString>, browsers_cache: Option<PathBuf> }`
built by `E2eEnv::from_process()` at the CLI seam. Contract tests construct it
with a temp-dir stub PATH. `std::env::set_var` is unsafe in edition 2024 and
races under the workspace's parallel test runs; this is the `ComposeRunner`
injection precedent.

**D11 — `session login` and the e2e leaves stay in the MCP catalog.**
`adopt` (which emits a one-time API token) is already there, so excluding
these would be inconsistent. `session login` still requires `IGNITION_PASSWORD`
in the server's environment, and `e2e init` still requires `--yes`. Recorded
as an `accept` disposition in the threat register.

**D12 — `tests/example.spec.mjs` ships TWO tests and skips the browser one honestly.**
A tag round-trip test (`writeTags` then `waitForTag`) that passes on any
gateway with the bundle deployed, and a Perspective-shell test that navigates,
asserts the response status is under 500 and the document title is non-empty —
and calls `test.skip()` with a message naming `--run-project` when the
navigation answers 404. A fresh rig with no custom views must produce a green
run.
