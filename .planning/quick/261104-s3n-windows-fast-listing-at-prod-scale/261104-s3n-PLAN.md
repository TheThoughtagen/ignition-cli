<objective>
Make `ign deploy` reads of Windows gateway hosts fast at production scale and add production-scale tests so a per-folder listing regression cannot ship again.

On a Windows host, `SftpTransport::discover` walks each requested tree level by level and lists every folder with sftp `ls -la`. The Windows sftp server costs about 0.8 s per folder plus 3.5 s per session, so the production tag tree (7,500 folders) takes about 100 minutes per read (BRIEF Problem). The fix lists every requested tree on Windows with a small fixed number of PowerShell calls that reuse the winps machinery, and keeps every safety property (BRIEF Fix). Downloads stay as they are; their session count is measured and reported, not changed (BRIEF Fix, last paragraph).

Purpose: one read of the production tree drops from about 100 minutes to under 2 minutes, `verify --node both` and `apply` stop taking hours, and four layers of tests at production shape gate every later deploy transport change (BRIEF Production-scale testing, the user's explicit ask).

Output: the generator, the offline RED-then-green connection-count tests, the Windows listing change, the local timed rows, the live VM gate with before/after numbers and an exact restore, the docs note, and SUMMARY.
</objective>
