<objective>
Register the `workspace push` clap leaf in `GUARDED_OPS` so the MCP surface can confirm it.

Today the guard lives entirely inside `ignition-core`'s `actions::workspace::workspace_push` (the dispatch arm hands it `cli.yes` and the action calls `require_confirmation(yes, &preview)`). Because there is no `require_confirmation` site and no `// guarded:` marker in main.rs, the verb never made it into `GUARDED_OPS` — so the MCP catalog derives no synthetic `confirm` property, `execute`'s fail-closed argument set rejects `confirm`, and the verb is permanently un-confirmable over the protocol. Live `tools/list` against `ign mcp serve` (verified 2026-09-20, ign 1.2.0) shows `workspace_push` with only `delete` and `path`; a call refuses `confirmation_required` with no way to answer.

Purpose: restore SC-2 parity — every `--yes`-guarded CLI verb is confirmable over MCP via the optional `confirm` field, and nothing else becomes confirmable.
Output: one GUARDED_OPS entry + its dispatch-site marker, two per-leaf tests in mcp.rs, and the README notes.
</objective>
